# ExpenseFlow — Handoff

This is a proof-of-concept expense submission and approval API, not a production system. This doc is for whoever has to run, deploy, or operate it next.

## What it does

One user journey, four moving parts:

1. **Submit an expense** (`POST /expenses`) — recorded as `PENDING`.
2. **List / fetch expenses** (`GET /expenses`, `GET /expenses/{id}`), optionally filtered by status/category.
3. **Approve or reject** a pending expense (`POST /expenses/{id}/approve`, `POST /expenses/{id}/reject`) — a one-way transition out of `PENDING`.
4. **Generate spending insights** (`GET /reports/insights`) — summarizes all stored expenses and asks Claude for three bullet points.

A Streamlit UI (`ui/app.py`) wraps all four for manual use. See `README.md` for setup, running, and the full endpoint reference — this doc doesn't repeat that.

## How it works

- **Request flow:** FastAPI routes (`app/routes.py`) → a per-request SQLAlchemy session (`app/db.py`'s `get_db` dependency) → a single SQLite file, `expenseflow.db`.
- **Startup:** the `lifespan` hook in `app/main.py` calls `init_db()`, which runs `Base.metadata.create_all()` — creates the `expenses` table if it's missing. There is no migrations tool (no Alembic); `create_all` only adds missing tables, it never alters existing columns.
- **Money:** every amount is an integer in minor units (see `docs/adr/0001-money-as-integer-minor-units.md`). There's no `Decimal`/float amount anywhere in the schema.
- **Currency conversion is not implemented.** `app/routes.py` has a `TODO` where a real FX lookup should go. Today, `amount_base_minor` is just a copy of `amount_minor`, `fx_rate` is hardcoded to `1.0`, and `base_currency` is always `"INR"` — regardless of what currency was submitted. Anyone consuming `amount_base_minor` today for non-INR expenses is getting the wrong number.
- **Approval workflow:** `_decide()` in `app/routes.py` checks the expense is currently `PENDING` before writing a new status; if not, it returns `409` instead of overwriting a prior decision. This check-then-write happens inside a single request/session — fine for one process, not a guaranteed atomic compare-and-swap if you ever run multiple app instances against the same SQLite file.
- **Insights** call the Anthropic API synchronously inside the request (`app/insights.py`). On any `anthropic.APIError` — including a missing/invalid API key — the endpoint does **not** return an error; it returns `200` with a fixed fallback string. The one `logger.error(...)` call there is the only diagnostic signal that a call actually failed.

## What a deployment engineer needs to know

- **No auth.** Every endpoint, including approve/reject, is open to anyone who can reach the process. Do not put this on the open internet as-is.
- **No CORS configured.** If the UI (or any other frontend) is served from a different origin than the API, browser calls will fail until `CORSMiddleware` is added — it isn't there today.
- **No health-check endpoint.** There's no `/health` or `/healthz`. `/docs` (Swagger UI, auto-generated by FastAPI) is the closest thing to a liveness probe today.
- **SQLite is the only datastore, and it's a single file** (`expenseflow.db`, path hardcoded in `app/db.py`, not configurable via env var):
  - Not safe for multiple concurrently-writing app instances/processes — scaling out means moving to a real database, not just adding uvicorn workers.
  - No backups, no rotation. If this data matters, back up the file yourself.
  - If you containerize this, the DB resets on every restart unless you mount a persistent volume at the process's working directory.
- **One secret:** `ANTHROPIC_API_KEY`, read from the environment via `python-dotenv`, used only in `app/insights.py`. The app starts fine without it — only `GET /reports/insights` silently degrades (see above). There is nothing else to configure as a secret.
- **No dependency lock file.** There's no `requirements.txt` or `pyproject.toml` in the repo — see `README.md` for the package list that was actually installed and tested. Pin these before deploying, or a redeploy can silently pick up a breaking upstream version.
- **No `.gitignore` exists yet.** `.env`, `.venv/`, and `expenseflow.db` are currently untracked but not excluded by anything — a careless `git add .` would commit the API key and the database file. Add a `.gitignore` before this repo is pushed anywhere shared.
- **No Dockerfile, CI pipeline, or process supervisor config** (Procfile, systemd unit, etc.) exists. Packaging and process supervision haven't been decided yet.
- **No logging configuration.** Whatever the default Python logging setup does with `logger.error(...)` calls is all you get today; make sure the process's stdout/stderr is captured wherever this runs.
- **Ports:** the API defaults to `8000` (via `python -m uvicorn app.main:app`), the Streamlit UI to `8501` (via `streamlit run ui/app.py`). Both are set by CLI flags at launch, not by anything in this repo.

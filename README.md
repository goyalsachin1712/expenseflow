# ExpenseFlow

A small expense submission and approval API (proof of concept, not production).

One user journey: submit an expense, have it normalized to a base currency, then approve or reject it. A Streamlit front end (`ui/app.py`) is included for exercising the API from a browser.

## What it does

- **Submit an expense** (`POST /expenses`) — amount, currency, category, description, and submitter are recorded. The expense starts in `PENDING` status.
- **List / fetch expenses** (`GET /expenses`, `GET /expenses/{id}`) — list can be filtered by `status` and/or `category`.
- **Approve or reject** a pending expense (`POST /expenses/{id}/approve`, `POST /expenses/{id}/reject`) — a one-way transition out of `PENDING`, with an optional decision note.
- **Generate spending insights** (`GET /reports/insights`) — sends a summary of all stored expenses to Claude and returns three short bullet-point insights.

All monetary amounts are stored as integer minor units (e.g. paise for INR), never as floats.

> **Known limitation:** currency conversion is not implemented yet. `app/routes.py` has a `TODO` where the real FX lookup should go — today `amount_base_minor` is simply copied from `amount_minor`, `fx_rate` is hardcoded to `1.0`, and `base_currency` is always `"INR"` regardless of the currency you submit. Don't rely on the returned `amount_base_minor` for non-INR expenses yet.

## Stack

- Python (3.10+; the checked-in `.venv` in this repo was built with 3.10.12)
- FastAPI + Uvicorn — the API (`app/main.py`)
- SQLAlchemy ORM on SQLite (`expenseflow.db`, created automatically on startup)
- Pydantic v2 — request/response models (`app/schemas.py`)
- Anthropic SDK — powers `GET /reports/insights` (`app/insights.py`)
- Streamlit + httpx + pandas — the optional UI (`ui/app.py`)
- pytest — test runner (no test modules exist in the repo yet)

There is no `requirements.txt` or `pyproject.toml` in the repo — install the packages directly as shown below.

## Setup on Windows

1. **Install Python 3.10+** if you don't already have it, and make sure `python` is on your `PATH`.

2. **Create and activate a virtual environment** (PowerShell):

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   If you're using `cmd.exe` instead of PowerShell:

   ```bat
   .venv\Scripts\activate.bat
   ```

   If PowerShell blocks the activation script with an execution-policy error, run this once in an elevated PowerShell session, then retry activation:

   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```

3. **Install dependencies.** For the API only:

   ```powershell
   pip install fastapi uvicorn sqlalchemy pydantic python-dotenv anthropic pytest
   ```

   Add these if you also want to run the Streamlit UI:

   ```powershell
   pip install streamlit httpx pandas
   ```

## Configure `.env`

The app reads environment variables via `python-dotenv`. Create a `.env` file in the project root:

```
ANTHROPIC_API_KEY=sk-ant-...
```

- `ANTHROPIC_API_KEY` — required for `GET /reports/insights` (`app/insights.py`). Without it, the endpoint doesn't error — it calls the Anthropic API with an empty key, which fails, and the endpoint returns the fallback string `"Insights are unavailable right now. Please try again later."`
- `API_BASE` — optional, read by `ui/app.py` only (not by the API itself). Sets the base URL the Streamlit UI uses to reach the API. Defaults to `http://127.0.0.1:8000`.

Note: the database location (`sqlite:///./expenseflow.db`) is hardcoded in `app/db.py` — there's no environment variable to change it.

## Run the server

```powershell
python -m uvicorn app.main:app --reload
```

- Serves on `http://127.0.0.1:8000` by default.
- On startup, `init_db()` creates the `expenses` table in `expenseflow.db` if it doesn't already exist — no separate migration step.
- Interactive API docs: `http://127.0.0.1:8000/docs` (Swagger UI, auto-generated by FastAPI).

## Run the Streamlit UI (optional)

With the API already running in one terminal, in another terminal (venv activated):

```powershell
streamlit run ui/app.py
```

Opens at `http://localhost:8501` by default. It lets you submit an expense, approve/reject pending expenses, view the full expense table (with status color-coded: yellow = pending, green = approved, red = rejected), and generate insights.

## Run the tests

```powershell
python -m pytest -q
```

At present there are no test files in the repo (no `tests/` directory, no `test_*.py` modules), so this command will report `no tests ran`. `docs/ARCHITECTURE.md` describes an intended `tests/test_expenses.py`, but it hasn't been written yet.

## Endpoint reference

All request/response bodies are JSON. Amounts are always integer minor units.

### `POST /expenses`

Create a new expense. Status is set to `PENDING`.

**Request body** (`ExpenseCreate`):

| Field | Type | Notes |
|---|---|---|
| `description` | string | required |
| `amount_minor` | integer | required, must be `> 0` |
| `currency` | string | required, must be a 3-letter alphabetic code (case-insensitive; stored uppercased) |
| `category` | string | required |
| `submitted_by` | string | required |

```json
{
  "description": "Client dinner",
  "amount_minor": 450000,
  "currency": "usd",
  "category": "Meals",
  "submitted_by": "alice"
}
```

**Response `201`** (`ExpenseOut`):

```json
{
  "id": 1,
  "description": "Client dinner",
  "amount_minor": 450000,
  "currency": "USD",
  "category": "Meals",
  "submitted_by": "alice",
  "amount_base_minor": 450000,
  "base_currency": "INR",
  "fx_rate": 1.0,
  "fx_rate_fetched_at": "2026-09-15T10:24:17.839542",
  "status": "PENDING",
  "created_at": "2026-09-15T10:24:17.840081",
  "decided_at": null,
  "decision_note": null
}
```

(Note `amount_base_minor` above equals `amount_minor` — see the currency-conversion limitation noted at the top of this file.)

**Errors:** `422` if `amount_minor <= 0` or `currency` isn't a 3-letter alphabetic code.

### `GET /expenses`

List expenses, optionally filtered.

**Query params (both optional):**
- `status` — exact match against `PENDING`, `APPROVED`, or `REJECTED`
- `category` — exact match

**Response `200`:** JSON array of `ExpenseOut` objects (see shape above). Empty array if nothing matches.

### `GET /expenses/{expense_id}`

Fetch a single expense.

**Response `200`:** one `ExpenseOut` object.
**Errors:** `404` if no expense with that id exists.

### `POST /expenses/{expense_id}/approve`

Transition a `PENDING` expense to `APPROVED`.

**Request body (optional)** (`DecisionIn`):

```json
{ "note": "Within policy limit" }
```

If omitted, `note` is `null`.

**Response `200`:** the updated `ExpenseOut`, with `status: "APPROVED"`, `decided_at` set to the current UTC time, and `decision_note` set from the request.

**Errors:**
- `404` if the expense doesn't exist.
- `409` if the expense's current status is not `PENDING` (no re-deciding an already-decided expense).

### `POST /expenses/{expense_id}/reject`

Same request/response shape and error conditions as `approve`, but sets `status: "REJECTED"`.

### `GET /reports/insights`

Summarizes **all** expenses in the database (regardless of status) and asks Claude for exactly three short bullet-point insights.

**Response `200`:**

```json
{ "insight": "- ...\n- ...\n- ..." }
```

If the Anthropic API call fails for any reason (missing/invalid key, network error, etc.), `insight` is the fixed fallback string `"Insights are unavailable right now. Please try again later."` instead of an error response — this endpoint does not return a non-2xx status on failure.

There are no `DELETE` or `PUT` endpoints.
